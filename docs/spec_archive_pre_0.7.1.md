# FramePilot 项目规格

版本：0.7（双阶段本机 YOLO：标注辅助 → 全量后训现场部署模型；千问预标注已放弃）

日期：2026-10-29

阶段：产品主线已明确为**双阶段本机 YOLO**，**放弃千问云端预标注**。

1. **标注辅助阶段（当前 M5）**：先人工标注少量种子样本 → 本机训练 YOLO detect → 用该权重对剩余图片做插件预标注 → 人工在原网站审核修正；可按 M5.4 迭代补标再训。
2. **现场部署阶段（M6）**：当项目中需要标注的图片**全部**经人工确认完成后，再用全量已确认标注训练一版面向工业现场部署的 YOLO 模型（导出/转换/上板不在本阶段插件范围内，但规格承认这是最终目标）。

实现状态：M5.1 / M5.3 已落地（可用现成权重）；M5.2 可用现成权重跳过；M6 仅规格立项，未实现专用训练交付。示例库与模拟/收录保留。历史 M3 千问说明作档案留存。

## 1. 项目目标

开发 Edge 浏览器扩展，读取原网站当前图片及项目类别，调用**本机 YOLO**生成初始矩形标注，并通过平台适配器写入原网站可编辑的标注数据，减少从零寻找目标和画框的重复操作。最终在项目全量标注完成后，用已确认数据训练可部署到工业现场的检测模型；插件本身仍只负责预标注写入，审核与保存在原网站。

**插件只负责最开始的预标注。人工移动、缩放、删除、补框、修改类别、审核确认、保存及数据集导出，全部在原网站中使用其现有功能完成。插件不提供独立审核界面，不管理审核状态，不建立独立保存或导出流程。**

| 组件 | 职责 |
| --- | --- |
| Edge 扩展 | 获取当前图片及类别，触发预标注，显示请求状态，将结果交给原网站 |
| AI 服务 | 分析图片，返回统一格式的初始框及类别 |
| 平台适配器 | 映射原图坐标和平台类别 ID，创建原网站可编辑的原生标注 |
| 原网站 | 标注显示、人工修改和补漏、审核、保存、导出以及训练流程 |

核心指标是完成同等审核要求的单张图片所需总时间，而不是模型独立标注准确率。当前不设模型准确率门槛；人工最终审核是必经步骤。经过审核不等于保证零错误。

## 2. 范围与阶段

### M1：本地最小通信链路（核心流程已验证）

- 本机 FastAPI 服务提供健康检查、测试网页和测试标注接口。
- 测试网页一次加载一张本地 PNG 或 JPEG 图片。
- Edge 扩展仅在本地测试网页启用，注入“生成测试框”按钮。
- 点击后，经扩展后台请求本机服务，返回确定性的模拟标注框。
- 网页通过明确的数据接口接收结果并显示矩形，不模拟鼠标操作。
- 显示“模拟结果，尚未接入 AI”，不将测试框描述为真实识别结果。
- 显示处理中、成功、失败状态；失败后允许重试。

本地网页仅用于验证通信、坐标和消息传递，不是正式工作入口。

### M2：原网站调查与模拟预标注接入（正常流程已验证）

- 先只读调查原网站当前图片来源、原始尺寸、图片/任务标识和项目类别表。
- 确认原网站标注数据结构、创建标注的方法、编辑能力和保存行为，再确定具体适配方式。
- 在目标标注页面提供预标注按钮，用模拟结果验证原生标注创建链路。
- 结果必须进入原网站的标注数据，使用户能够使用原网站已有工具编辑；仅叠加不可编辑的视觉框不算接入完成。
- 插件不触发提交审核、确认完成或最终保存。若网站创建标注即自动保存草稿，调查时记录该行为，遵循其正常机制，不将草稿写入等同于人工确认。
- 不重做原网站的人工编辑、审核、保存或导出功能。

### M3：真实 AI 预标注

- 在已验证的网站适配链路上，将模拟接口替换为真实预标注接口；后端接收图片和原网站允许使用的类别列表，调用视觉模型。
- 模型适配层将返回值转换成统一坐标和类别格式。
- 标注单位为单个独立物体。同类的多个可辨认实例分别输出框并复用同一个类别 ID；相邻、接触或部分遮挡的独立黑色板件也分别标注，不用一个大框包住多个板件。提示词和 JSON 示例明确此规则，实际数量由目标图片决定，不照搬示例数量，也不按固定数量强行拆框。类别示例只帮助判断外观，后端及网站适配器逐框保留同类多实例。
- API 密钥仅在后端配置，不放入扩展或页面。
- 按用户要求改用阿里云百炼的通义千问视觉模型，默认 `qwen3-vl-flash`，通过北京地域的 Chat Completions 兼容接口调用。后端 `.env` 使用 `DASHSCOPE_API_KEY` 和 `QWEN_MODEL`；不读取或回退到原 OpenAI 密钥。
- 使用非思考模式和 JSON Object 输出，后端严格校验字段、类别、坐标及完整响应后才转换为标注。图片发送提示明确写明“阿里云百炼（通义千问）”及按用量计费；模拟测试仍不发送图片。
- 保留模拟按钮；增加真实 AI 按钮，用户勾选图片发送提示并点击后才读取、发送当前图片和项目类别。不得因打开页面、切图或轮询状态自动发送图片。
- 从原图缓存获取没有标注叠层的画面，按比例缩小至最长边 1600 像素，编码为 JPEG；单张编码文件不超过 2 MiB。不发送文件名、网站账号或 Cookie；项目名仅作为本地示例图按项目隔离的键发送到本机服务（哈希成目录名），不发送给模型。
- 千问模型输出使用 0～1000 的归一化整数边界，后端校验后按 `坐标 × 原图尺寸 / 1000` 换算为原图像素；不猜测输出单位。真实类别使用项目原有 ID，不将所有框强制映射成当前选中类别。
- 请求前后核对同一图片和类别表；已有标注、非法输出、超时和空结果均不写入。一次最多 100 个框，不自动重试模型请求。
- 模型请求最长 22 秒，扩展后台 25 秒超时，页面 30 秒超时；所有失败保留原网站数据。暂不做异步任务和批量处理。
- 结果仍交给原网站，由人在原网站中审核和保存。
- 使用人工计时或原网站可用记录测量等待、修改及审核耗时，不为计时增加插件审核流程。

### M3+：已确认人工标注示例库（本次新增，推理时视觉少样本）

从用户已在原网站确认的人工标注建立示例库，并在后续 AI 预标注时作为「类别外观参考」随请求发送。这是推理时视觉少样本（few-shot），不是模型训练或微调，任何界面与文档都不得写成“训练完成”。

- 采集入口为侧边栏「收录当前图片的标注」按钮：对当前图片的原生标注（含经人工修正、确认正确的 AI 框）先逐框校验，再在确认弹窗中展示项目/图片/框数与各类别计数，并注明“仅本机保存、勾选同意并点预标注时才随 AI 请求发送”；用户点「确认收录」才写入示例库。第一版只收录当前图片，不做历史批量；不自动收录 AI 输出，只有用户明确确认后才收录。
- 示例按「项目 + 类别」隔离存放于本机 `server/references/<sha256(project_id)[:16]>/`，每类最多 5 张，超出提示用户（不静默覆盖）；同一来源 + 类别 + 框内容去重。沿用轻量本地文件，不新增数据库。
- 示例库侧边栏按需拉取（不并入 1 秒轮询），按类别显示有效数量与缩略图，可删除单张示例；项目之间隔离。
- AI 预标注时，后端按确定性轮转取每个启用类别最多 2 张、全请求最多 12 张示例图，标记为“类别外观参考”，最后一张图是待标注目标，只返回目标图上的框；`source_id`/文件名/项目名等本地来源信息不进入模型请求。本地采集、预览、删除均不调用模型。
- 采集资格与预标注资格拆分：有标注的图片仍禁止 AI/模拟预标注，但允许收录；空标注图片可预标注但不能收录。类别改名或删除导致 ID 重排后，旧示例不会错误关联到别的类别（按采集时类别名匹配）；项目改名会使哈希目录变化、旧示例不再自动关联（文件保留，需重新采集），此限制已写入文档。兼容旧版 `<class_id>.jpg` + `index.json` 示例格式，只读不迁移。

### M4：实际流程验收与效率评估

在原网站上验证真实图片预标注、人工修正及保存的完整流程，并比较纯人工和辅助标注总耗时。最终保存格式和数据集格式由原网站决定。


### M5：少量人工标注 → 本机 YOLO → 自动预标注（标注辅助阶段）

目标：用约 **50 张** 已确认人工标注作为种子，在本机训练 YOLO 目标检测模型，再用该模型对剩余未标注图片生成初始框，写入原网站后由人工审核保存。此阶段产出的权重服务于**加速标注**，不要求直接等于现场部署模型。核心仍是缩短单张总耗时，不是追求模型独立准确率；**不得跳过人工审核**。

与 M3/M3+ 的关系：示例库与模拟路径保留；**产品预标注引擎仅为本机 YOLO**（侧边栏另保留「模拟测试」）。千问云端预标注方案已放弃，不再作为可选引擎。

本机环境约束（已核实，写入规格供实现对照）：Windows，NVIDIA GeForce RTX 4060 Laptop（约 8GB 显存），CUDA 驱动可用；建议独立 Python **3.12** 虚拟环境安装 Ultralytics/PyTorch（项目主 `.venv` 若为 3.14，不强制混用）。训练与推理均在本机，不上传训练集到第三方训练云（除非用户另行授权）。

#### M5.1 训练集导出

- 从「已确认、可用于训练」的人工标注生成 YOLO detect 数据集：每张图对应同名 `.txt`，每行 `class_id x_center y_center width height`（归一化 0～1），另有 `classes.txt` / `data.yaml`。
- 第一版优先打通一条可复现导出路径：要么对接原网站已有导出，要么由插件/本机工具从当前可读的原图缓存 + 原生标注批量写出。具体入口调查后写入任务卡；**不得**要求用户改用插件内编辑器完成审核。
- 导出目录按项目隔离，放在本机项目数据区（例如 `server/datasets/<project_key>/` 或用户指定路径），不进 Git。
- 种子规模约定：第一版目标约 **50 张** 已标注图，用于跑通训练与自动预标注；验收标准是「流程通、多数图有可用初始框」，不承诺「几乎不用改」。类别数、每图目标数在任务卡记录实测值。
- 只导出用户明确选中或整批确认的样本；不把未审核的纯 AI 框默认为训练真值，除非用户勾选「将当前框视为已确认」。

#### M5.2 本机训练

- 使用 Ultralytics YOLO **detect**（建议起步权重 `yolov8n.pt` 或 `yolov8s.pt`，适配 8GB 显存）。
- 提供本机可重复的训练命令/脚本（独立 3.12 环境），记录 epochs、imgsz、batch、device、数据划分（建议至少留一小部分验证集，即便总数约 50 张）。
- 产出：本机权重文件（如 `best.pt`）与简短训练摘要（最终指标、耗时、数据张数）；不把训练日志当验收通过证明。
- 训练失败（OOM、缺依赖、数据为空）必须明确报错，不得静默落到演示框。

#### M5.3 本机 YOLO 推理预标注

- 后端新增本地推理适配：加载用户指定的本机权重，对当前图做 detect；默认建议 `confidence=0.25`、`IoU=0.45`（服务端校验合法范围），参数可在配置或请求中覆盖。
- 输出转换成既有统一标注结构（原图像素 x/y/width/height + 项目类别 ID/名称），再走已验证的平台适配器写入原网站。
- 类别映射：模型 `class_id` 必须对应导出时的 `classes.txt` / 项目类别表；未知类别拒绝写入。
- 与千问相同的安全规则：仅用户主动触发；已有标注不覆盖；切图/类别变更/非法输出/空结果不写入；空结果算一次成功的「无框」响应并提示，不自动确认无目标。
- 推理在本机完成，图片不发往阿里云；千问预标注入口已退役。
- 第一版以**当前单张**预标注为主；整页/整项目批量排队可在 M5.3 后单独立项，本规格不要求一次做完。

#### M5.4 迭代补标（可选同阶段验收）

- 支持「YOLO 预标注 → 原网站人工修正 → 将修正结果纳入训练集 → 再训」的循环说明与最小工具支持。
- 不自动覆盖旧权重；新权重需用户确认后才切换为预标注默认模型。

### M6：全量标注完成后的现场部署模型（新增）

目标：在**同一项目**中，当需要标注的图片均已完成人工审核确认后，用**全量已确认标注**再训练一版 YOLO detect，作为可部署到工业现场的模型候选。此阶段强调数据完整与可复现训练，不要求 FramePilot 插件完成板端转换或现场上线。

范围：

- 全量训练集导出（复用 M5.1 路径与约定，规模为项目全部已确认图，不再限约 50 张种子）。
- 本机（或用户指定本机环境）训练命令/脚本与权重产物；记录数据规模、划分、超参与摘要指标。
- 与标注辅助权重分离存放（例如 `server/models/assist/` 与 `server/models/field/`，具体目录在实现任务卡中定）；不得在用户未确认时用现场候选权重静默覆盖预标注默认权重。
- 文档说明：现场部署（RK 等板端、量化、推理服务）由现场部署流程承接；本规格只要求「全量确认数据 → 可复现训出 detect 权重」。

验收（文档级先立，实现时再测）：

1. 能从全量已确认标注导出完整 YOLO detect 集。
2. 能按文档命令训出权重，并与标注辅助权重分目录保存。
3. 不把未审核框默认当训练真值；不跳过人工确认门槛。

### 已有测试网页的处理


此前按 v0.1 开发的人工编辑、审核和 JSON/YOLO 导出代码保留为本地测试辅助工具。它们不属于插件正式交付范围，不要求用户转移到测试网页完成审核，也不作为后续阶段的前置验收任务。本次变更只修订规格，不删除现有测试代码。

## 3. 当前不做

- 插件内的人工编辑器、审核确认、审核状态管理、最终保存和数据集导出（训练用 YOLO 数据集导出除外，见 M5.1）。
- SAM 及非 YOLO detect 的分割/多任务模型。
- 批量自动保存、跳过人工审核，或把未确认 AI 框默认当训练真值。
- 修改公司训练平台流程，或未经调查直接改原网站后台。
- 把训练集或权重默认上传到第三方云训练/推理服务（本机 Ultralytics 训练与推理除外）。
- 用户系统、业务数据库、多机云部署。
- 任意网站通用标注支持。
- 第一版不要求整项目无人值守批量自动标完（可后续单独立项）。

## 4. 用户流程

产品闭环（双阶段）：

1. 人工在原网站标注少量种子 → 导出并本机训练标注辅助 YOLO → 侧边栏「预标注」跑剩余图 → 人工审核修正（可迭代再训）。
2. 项目所需图片全部确认完成后 → 导出全量已确认数据 → 再训现场部署候选 YOLO（M6）；上板与现场集成另案。

M1：打开测试网页 → 加载图片 → 点击生成测试框 → 等待接口 → 查看框。

正式 MVP：在原网站打开待标注图片 → 点击工具栏图标打开侧边栏 → 在侧边栏点击预标注（本机 YOLO）→ 获取初始框 → 写入原网站原生标注数据 → 用户用原网站工具审核、补漏和修正 → 按原网站流程保存。

V1 默认仅对尚无标注的当前图片执行初始标注；已有标注时提示用户在原网站处理，插件不清空、不覆盖、不自动合并。返回结果写入前再次核对图片/任务标识和已有标注，若图片已切换或用户已添加标注，则丢弃此次结果并提示。重复点击不得重复创建框。

切图后的标注加载、未保存提醒及审核状态由原网站管理；插件只丢弃过期请求，不修改其他图片的数据。没有检测到目标时只提示“未生成标注，请在原网站检查”，不自动确认无目标或审核通过。


YOLO 主线（M5）：在原网站完成约 50 张种子图的人工标注并确认 → 导出本机 YOLO 训练集 → 本机训练得到权重 → 侧边栏选择本机 YOLO，对未标注图片点预标注 → 初始框写入原网站 → 人工审核修正并保存 → 可选：把修正样本并入训练集再训。

示例库流程：在原网站人工标注并确认框/类别正确 → 打开该图片，点侧边栏「收录当前图片的标注」→ 确认弹窗核对项目/图片/框数/各类别计数后点「确认收录」→ 插件读取原生标注、从原图缓存逐框裁剪，按项目 + 类别存到本机示例库 → 累积足够后，勾选发送许可点「预标注」，后端自动带上已启用类别的示例图作为外观参考。人工修改、审核、保存、导出始终在原网站完成。

## 5. 数据约定

内部使用原图像素坐标，左上角为原点，x 向右、y 向下。框表示为 x、y、width、height；不使用页面缩放后的像素保存数据。

当前本地模拟接口示例（兼容已有实现）：

```json
{
  "schema_version": "1.0",
  "image_id": "本次加载图片的唯一标识",
  "image_width": 1000,
  "image_height": 800,
  "source": "mock",
  "objects": [
    {
      "id": "box-1",
      "class_id": 0,
      "class_name": "part_A",
      "x": 100,
      "y": 80,
      "width": 200,
      "height": 160
    }
  ],
  "review_status": "pending"
}
```

- M1 模拟类别为 `part_A`、ID 0；测试网页另有演示类别 `part_B`。正式接入以原网站项目类别及稳定 ID 为准，不把演示类别硬编码到平台数据中。
- 坐标必须是有限数值，框宽高大于 0，边界位于原图范围内。
- 类别必须来自项目类别表，不能根据每张图片临时重新编号。
- 前后端检查数据格式；非法返回值显示错误，不直接写入标注。
- 图片缩放时按比例显示框；页面留白偏移不计入原图坐标。
- 上述模拟接口的 `review_status: pending` 是历史测试字段，保留兼容，不代表插件管理审核流程。正式适配时不据此写入或推进原网站审核状态，也不要求原网站使用这一字段。
- 统一返回值用于传输初始框；平台适配器转换为原网站的标注结构。若原网站提供来源字段，可记录 AI 来源；不擅自添加平台不支持的字段。
- 原网站负责最终保存及导出格式。插件不以 JSON/YOLO 下载作为完成预标注的出口。

以下 YOLO 换算仅作为适配参考和现有测试工具说明，不构成插件导出功能要求。原网站需要该格式时才使用；每行格式为 `class_id x_center y_center width height`，四个坐标值归一化至 0～1：

```text
x_center = (x + width / 2) / image_width
y_center = (y + height / 2) / image_height
width_normalized = width / image_width
height_normalized = height / image_height
```

### 示例库存储约定

- 位置：`server/references/<sha256(project_id)[:16]>/`。`project_id` 是原网站项目名，仅作为本地隔离键（哈希成目录名），不发送给模型。
- v2 元数据：`examples.json`，形如 `{"version":2,"examples":[{"id","class_id","class_name","file","source_id"}]}`；每张示例的图片文件为裁剪后的 JPEG（最长边 640px），缩略图由后端按最长边 128px 生成。每类最多 5 张。
- `id` 由 `sha256(source_id:class_id:内容哈希)[:16]` 生成，用于同一来源 + 类别 + 框内容去重；重试/重复采集只跳过、不重复保存。
- 旧版格式（`<class_id>.jpg` + `index.json`）继续可读、可删除，但不迁移。示例是否归属于某类别由 `class_id` 在当前类别表内、且 `class_name` 与当前类别名一致共同决定，防止类别改名/删除后 ID 重排导致误关联。
- 来源信息（文件名、source_id）只用于本机去重和定位，不进入模型请求体。

## 8. 验收标准

### M1 必须通过

1. 服务可以启动，健康检查返回成功。
2. 扩展可在 Edge 加载，本地测试页面显示按钮。
3. 没有图片时不能发送标注请求，并有提示。
4. 加载 PNG/JPEG 后点击按钮，出现模拟框且标明模拟来源。
5. 使用 1000×800 图片时，返回框为 (100, 80, 200, 160)。
6. 缩放浏览器或改变窗口宽度后，框与图片对应位置保持一致。
7. 停止后端再请求，页面显示失败提示；恢复后可以重试。
8. 请求期间切换图片，旧响应不会污染新图片。
9. 重复点击不会叠加重复框或静默覆盖已有结果。

### M2 必须通过

1. 从原网站正确读取当前图片、原始尺寸、图片/任务标识及类别表。
2. 点击插件按钮后，模拟框写入原网站原生标注数据；坐标及类别映射正确。
3. 用户无需打开独立测试网页，即可用原网站工具移动、缩放、删除、补框或修改类别。
4. 用户使用原网站已有审核和保存流程；插件没有独立审核或最终保存步骤，也不自动提交审核。
5. 已有标注不会被覆盖；请求途中人工新增标注、切图、重复点击或迟到响应不会造成错图写入或重复创建。
6. 失败和空结果有提示，不清除已有数据，也不替用户确认无目标。
7. 明确记录原网站是否自动保存草稿；无论采用何种草稿机制，插件都不把写入结果标记为已审核。

### M3 必须通过

1. 使用真实模型对当前图片及原网站类别生成初始标注，并通过已验证适配器写入。
2. 非法坐标、未知类别和格式错误不会直接写入网站；用户收到明确提示。
3. 模型失败后可以重试，且不破坏原网站当前标注；API 密钥只在后端配置。
4. 人工审核、修正和保存仍全部在原网站完成。
5. 使用伪造模型响应验证两个相邻的同类框在坐标换算和网站写入后仍为两个框，类别 ID 相同、框 ID 独立。再用真实图片检查单个、相邻多个及部分遮挡的目标；自动测试通过不代表模型分框效果已验收。

### M4 效率验证

在图片难度相近、审核要求相同的条件下，对比纯人工与 AI 辅助标注。记录模型等待时间、人工操作时间和总完成时间，报告样本量及平均值/中位数。可以交叉安排两种流程以减少熟悉图片带来的偏差。

效率提升倍数 = 纯人工平均总耗时 / AI 辅助平均总耗时。

暂不承诺固定提升倍数，也不以模型准确率作为阻止原型开发的门槛。

4. 已有标注、切图、非法输出、空结果不破坏原网站数据；不跳过人工审核。
5. 模拟路径仍可用；YOLO 预标注不把图片发往阿里云百炼；千问预标注入口不可用。
6. 自动化测试可用伪造/轻量权重覆盖导出格式、类别映射与写入守卫；真实 GPU 训练与真实图效果须单独记录，不得与单测混称为同一验收。
