# AI Annotation Assistant 项目规格

版本：0.4（通义千问初始标注）

日期：2026-10-01

阶段：原网站模拟链路经用户验证；千问版本已获用户试用正向反馈，下一阶段进行小批量流程与效率验证

## 1. 项目目标

开发 Edge 浏览器扩展，读取原网站当前图片及项目类别，调用 AI 生成初始矩形标注，并通过平台适配器写入原网站可编辑的标注数据，减少从零寻找目标和画框的重复操作。

**插件只负责最开始的预标注。人工移动、缩放、删除、补框、修改类别、审核确认、保存及数据集导出，全部在原网站中使用其现有功能完成。插件不提供独立审核界面，不管理审核状态，不建立独立保存或导出流程。**

| 组件 | 职责 |
| --- | --- |
| Edge 扩展 | 获取当前图片及类别，触发预标注，显示请求状态，将结果交给原网站 |
| AI 服务 | 分析图片，返回统一格式的初始框及类别 |
| 平台适配器 | 映射原图坐标和平台类别 ID，创建原网站可编辑的原生标注 |
| 原网站 | 标注显示、人工修改和补漏、审核、保存、导出以及训练流程 |

核心指标是完成同等审核要求的单张图片所需总时间，而不是模型独立标注准确率。当前不设模型准确率门槛；人工最终审核是必经步骤。经过审核不等于保证零错误。

## 2. 范围与阶段

### M1：本地最小通信链路（核心流程已验证）

- 本机 FastAPI 服务提供健康检查、测试网页和测试标注接口。
- 测试网页一次加载一张本地 PNG 或 JPEG 图片。
- Edge 扩展仅在本地测试网页启用，注入“生成测试框”按钮。
- 点击后，经扩展后台请求本机服务，返回确定性的模拟标注框。
- 网页通过明确的数据接口接收结果并显示矩形，不模拟鼠标操作。
- 显示“模拟结果，尚未接入 AI”，不将测试框描述为真实识别结果。
- 显示处理中、成功、失败状态；失败后允许重试。

本地网页仅用于验证通信、坐标和消息传递，不是正式工作入口。

### M2：原网站调查与模拟预标注接入（正常流程已验证）

- 先只读调查原网站当前图片来源、原始尺寸、图片/任务标识和项目类别表。
- 确认原网站标注数据结构、创建标注的方法、编辑能力和保存行为，再确定具体适配方式。
- 在目标标注页面提供预标注按钮，用模拟结果验证原生标注创建链路。
- 结果必须进入原网站的标注数据，使用户能够使用原网站已有工具编辑；仅叠加不可编辑的视觉框不算接入完成。
- 插件不触发提交审核、确认完成或最终保存。若网站创建标注即自动保存草稿，调查时记录该行为，遵循其正常机制，不将草稿写入等同于人工确认。
- 不重做原网站的人工编辑、审核、保存或导出功能。

### M3：真实 AI 预标注

- 在已验证的网站适配链路上，将模拟接口替换为真实预标注接口；后端接收图片和原网站允许使用的类别列表，调用视觉模型。
- 模型适配层将返回值转换成统一坐标和类别格式。
- API 密钥仅在后端配置，不放入扩展或页面。
- 按用户要求改用阿里云百炼的通义千问视觉模型，默认 `qwen3-vl-flash`，通过北京地域的 Chat Completions 兼容接口调用。后端 `.env` 使用 `DASHSCOPE_API_KEY` 和 `QWEN_MODEL`；不读取或回退到原 OpenAI 密钥。
- 使用非思考模式和 JSON Object 输出，后端严格校验字段、类别、坐标及完整响应后才转换为标注。图片发送提示明确写明“阿里云百炼（通义千问）”及按用量计费；模拟测试仍不发送图片。
- 保留模拟按钮；增加真实 AI 按钮，用户勾选图片发送提示并点击后才读取、发送当前图片和项目类别。不得因打开页面、切图或轮询状态自动发送图片。
- 从原图缓存获取没有标注叠层的画面，按比例缩小至最长边 1600 像素，编码为 JPEG；单张编码文件不超过 2 MiB。不发送项目名、文件名、网站账号或 Cookie。
- 千问模型输出使用 0～1000 的归一化整数边界，后端校验后按 `坐标 × 原图尺寸 / 1000` 换算为原图像素；不猜测输出单位。真实类别使用项目原有 ID，不将所有框强制映射成当前选中类别。
- 请求前后核对同一图片和类别表；已有标注、非法输出、超时和空结果均不写入。一次最多 100 个框，不自动重试模型请求。
- 模型请求最长 22 秒，扩展后台 25 秒超时，页面 30 秒超时；所有失败保留原网站数据。暂不做异步任务和批量处理。
- 结果仍交给原网站，由人在原网站中审核和保存。
- 使用人工计时或原网站可用记录测量等待、修改及审核耗时，不为计时增加插件审核流程。

### M4：实际流程验收与效率评估

在原网站上验证真实图片预标注、人工修正及保存的完整流程，并比较纯人工和辅助标注总耗时。最终保存格式和数据集格式由原网站决定。

### 已有测试网页的处理

此前按 v0.1 开发的人工编辑、审核和 JSON/YOLO 导出代码保留为本地测试辅助工具。它们不属于插件正式交付范围，不要求用户转移到测试网页完成审核，也不作为后续阶段的前置验收任务。本次变更只修订规格，不删除现有测试代码。

## 3. 当前不做

- 插件内的人工编辑器、审核确认、审核状态管理、最终保存和数据集导出。
- 模型训练、YOLO/SAM 集成。
- 批量自动保存或跳过人工审核。
- 修改公司训练流程或直接接入尚未调查的平台。
- 用户系统、数据库、云部署。
- 任意网站通用标注支持。

## 4. 用户流程

M1：打开测试网页 → 加载图片 → 点击生成测试框 → 等待接口 → 查看框。

正式 MVP：在原网站打开待标注图片 → 点击插件预标注按钮 → 获取初始框 → 写入原网站原生标注数据 → 用户用原网站工具审核、补漏和修正 → 按原网站流程保存。

V1 默认仅对尚无标注的当前图片执行初始标注；已有标注时提示用户在原网站处理，插件不清空、不覆盖、不自动合并。返回结果写入前再次核对图片/任务标识和已有标注，若图片已切换或用户已添加标注，则丢弃此次结果并提示。重复点击不得重复创建框。

切图后的标注加载、未保存提醒及审核状态由原网站管理；插件只丢弃过期请求，不修改其他图片的数据。没有检测到目标时只提示“未生成标注，请在原网站检查”，不自动确认无目标或审核通过。

## 5. 数据约定

内部使用原图像素坐标，左上角为原点，x 向右、y 向下。框表示为 x、y、width、height；不使用页面缩放后的像素保存数据。

当前本地模拟接口示例（兼容已有实现）：

```json
{
  "schema_version": "1.0",
  "image_id": "本次加载图片的唯一标识",
  "image_width": 1000,
  "image_height": 800,
  "source": "mock",
  "objects": [
    {
      "id": "box-1",
      "class_id": 0,
      "class_name": "part_A",
      "x": 100,
      "y": 80,
      "width": 200,
      "height": 160
    }
  ],
  "review_status": "pending"
}
```

- M1 模拟类别为 `part_A`、ID 0；测试网页另有演示类别 `part_B`。正式接入以原网站项目类别及稳定 ID 为准，不把演示类别硬编码到平台数据中。
- 坐标必须是有限数值，框宽高大于 0，边界位于原图范围内。
- 类别必须来自项目类别表，不能根据每张图片临时重新编号。
- 前后端检查数据格式；非法返回值显示错误，不直接写入标注。
- 图片缩放时按比例显示框；页面留白偏移不计入原图坐标。
- 上述模拟接口的 `review_status: pending` 是历史测试字段，保留兼容，不代表插件管理审核流程。正式适配时不据此写入或推进原网站审核状态，也不要求原网站使用这一字段。
- 统一返回值用于传输初始框；平台适配器转换为原网站的标注结构。若原网站提供来源字段，可记录 AI 来源；不擅自添加平台不支持的字段。
- 原网站负责最终保存及导出格式。插件不以 JSON/YOLO 下载作为完成预标注的出口。

以下 YOLO 换算仅作为适配参考和现有测试工具说明，不构成插件导出功能要求。原网站需要该格式时才使用；每行格式为 `class_id x_center y_center width height`，四个坐标值归一化至 0～1：

```text
x_center = (x + width / 2) / image_width
y_center = (y + height / 2) / image_height
width_normalized = width / image_width
height_normalized = height / image_height
```

## 6. M1 接口与模块

本机地址：`http://127.0.0.1:8000`。

- `GET /health`：返回服务状态。
- `GET /demo/`：提供测试网页。
- `POST /api/annotations/mock`：接收 image_id、image_width、image_height，返回上述统一结构；不上传图片，也不调用外部模型。

模拟框按原图尺寸比例生成：x=10%、y=10%、width=20%、height=20%，保证结果可预测且能适配不同尺寸图片。

扩展 content script 负责按钮和页面适配，background service worker 负责请求本机服务；测试网页负责图片及可编辑标注数据。页面与扩展之间传递的数据需要进行结构校验。扩展权限只覆盖本地测试所需范围。

正式接入时，将测试网页适配替换为原网站适配器。仅在明确的目标站点及标注页面启用必要权限；具体读取和写入接口须调查后确认，不能假定直接向某个数组追加即可生效。优先使用原网站明确支持的数据接口或原生标注创建方法，不依赖模拟鼠标画框。

请求期间禁用重复操作；请求最长等待 30 秒。服务不可用、超时、返回格式错误均需给出可理解的提示，并保留用户已有数据。

## 8. 验收标准

### M1 必须通过

1. 服务可以启动，健康检查返回成功。
2. 扩展可在 Edge 加载，本地测试页面显示按钮。
3. 没有图片时不能发送标注请求，并有提示。
4. 加载 PNG/JPEG 后点击按钮，出现模拟框且标明模拟来源。
5. 使用 1000×800 图片时，返回框为 (100, 80, 200, 160)。
6. 缩放浏览器或改变窗口宽度后，框与图片对应位置保持一致。
7. 停止后端再请求，页面显示失败提示；恢复后可以重试。
8. 请求期间切换图片，旧响应不会污染新图片。
9. 重复点击不会叠加重复框或静默覆盖已有结果。

### M2 必须通过

1. 从原网站正确读取当前图片、原始尺寸、图片/任务标识及类别表。
2. 点击插件按钮后，模拟框写入原网站原生标注数据；坐标及类别映射正确。
3. 用户无需打开独立测试网页，即可用原网站工具移动、缩放、删除、补框或修改类别。
4. 用户使用原网站已有审核和保存流程；插件没有独立审核或最终保存步骤，也不自动提交审核。
5. 已有标注不会被覆盖；请求途中人工新增标注、切图、重复点击或迟到响应不会造成错图写入或重复创建。
6. 失败和空结果有提示，不清除已有数据，也不替用户确认无目标。
7. 明确记录原网站是否自动保存草稿；无论采用何种草稿机制，插件都不把写入结果标记为已审核。

### M3 必须通过

1. 使用真实模型对当前图片及原网站类别生成初始标注，并通过已验证适配器写入。
2. 非法坐标、未知类别和格式错误不会直接写入网站；用户收到明确提示。
3. 模型失败后可以重试，且不破坏原网站当前标注；API 密钥只在后端配置。
4. 人工审核、修正和保存仍全部在原网站完成。

### M4 效率验证

在图片难度相近、审核要求相同的条件下，对比纯人工与 AI 辅助标注。记录模型等待时间、人工操作时间和总完成时间，报告样本量及平均值/中位数。可以交叉安排两种流程以减少熟悉图片带来的偏差。

效率提升倍数 = 纯人工平均总耗时 / AI 辅助平均总耗时。

暂不承诺固定提升倍数，也不以模型准确率作为阻止原型开发的门槛。
