## 2. 目标与原则

开发 Edge 扩展：读取原网站当前图片与项目类别 → 调用**本机 YOLO**生成初始矩形框 → 经平台适配器写入原网站可编辑标注 → 缩短从零找目标与画框的时间。迭代再训与现场候选训练在**原网站**完成；训好的权重可用本插件 M5.5 接入。上板另案。

| 组件 | 职责 |
| --- | --- |
| Edge 扩展 | 取当前图与类别；触发预标注；显示状态；把结果交给原网站 |
| 本机服务 | YOLO 推理（及 mock）；返回统一格式初始框 |
| 平台适配器 | 原图坐标与平台类别 ID 映射；创建网站原生可编辑标注 |
| 原网站 | 显示、人工改与补漏、审核、保存、导出及后续训练流程 |

核心指标是「同等审核要求下单张总耗时」，不是模型独立准确率。人工最终审核必经；经过审核 ≠ 保证零错误。

## 3. 非目标

- 插件内人工编辑器、审核确认/状态管理、最终保存；**M5.4 迭代补标工具链与 M6 现场候选训练**（均在原网站完成）
- SAM 及非 YOLO detect 的分割/多任务模型
- 批量自动保存、跳过人工审核，或把未确认 AI/YOLO 框默认当训练真值
- 修改公司训练平台流程，或未经调查改原网站后台
- 默认把训练集/权重上传第三方云训练或云推理（本机 Ultralytics 除外）
- 用户系统、业务库、多机云部署；任意网站通用标注
- 第一版整项目无人值守批量标完（可后续单独立项）
- 恢复千问云端预标注产品路径

## 5. 用户流程

**正式 MVP（现行）**

1. 原网站打开待标注图 → 工具栏开 FramePilot 侧边栏  
2. 点「预标注」（或 Enter）→ 本机 YOLO → 初始框写入原生标注  
3. 用原网站工具审核、补漏、修正 → 按原网站流程保存  

V1 默认仅对**尚无标注**的当前图做初始标注；已有标注时提示在原网站处理，插件不清空、不覆盖、不自动合并。写入前再核图片/任务标识与已有标注；切图或中途新增标注则丢弃结果。重复点击不得重复建框。空结果只提示「未生成标注，请在原网站检查」，不自动确认无目标。

**YOLO 主线（M5）**

约 50 张种子人工确认 → 导出训练集 → 本机训练（或现成权重）→ 对未标注图点「预标注」→ 审核保存 → 可选迭代再训。

**全量后（原网站）**

项目所需图全部确认后的全量导出与现场候选训练在**原网站**完成；本插件不交付 M6。上板另案。

**保留能力**

- 「模拟测试」：不传图片字节，写固定比例模拟框（联调适配器用）  
- ~~「收录当前图片的标注」/ 示例库~~：**已移除（0.7.4）**

**历史测试网页**

v0.1 本地编辑/审核/JSON·YOLO 导出代码保留为测试辅助，非正式交付，不要求用户迁到测试页审核。

## 6. 系统结构

```text
侧边栏 (sidepanel)  ↔  background  ↔  目标标签 content  ↔  MAIN 平台适配器
                              ↓
                     本机 FastAPI :18000
                     (mock / yolo / health)
```

- 每个操作显式绑定 `tabId` / project / image / `requestId`；权威每标签状态在 content；侧边栏只做视图与触发。  
- 不同标签不共享类别选择、请求状态。  
- 仅用户主动触发预标注；打开侧边栏、切标签、轮询**不**构成推理授权。  
- 密钥若仍留在 `.env`（如旧 `DASHSCOPE_API_KEY`）**不参与**现行预标注。  
- 正式站点权限仅限明确目标标注页；优先网站原生创建标注 API，不模拟鼠标画框。详见 `docs/platform-adapter.md`。

## 7. M5 / M6 范围说明

### M5 标注辅助（约 50 张种子 → 加速标注）

产出权重服务于**加速标注**，不要求等于现场部署模型；**不得跳过人工审核**。

本机约束：训练与推理在本机；不上传训练集到第三方训练云（除非用户另行授权）。

#### M5.1 训练集导出 — **已实现**

- YOLO detect：每图同名 `.txt`，行格式 `class_id x_center y_center width height`（0～1）；另有 `classes.txt` / `data.yaml`。  
- 工具：`tools/prepare_yolo_dataset.py`；说明 `docs/M5_1_YOLO_DATASET.md`。优先原网站「导出 YOLO Zip」再整理到 `server/datasets/<project_key>/`（不进 Git）。  
- 约 50 张种子跑通流程；验收「流程通、多数图有可用初始框」，不承诺「几乎不用改」。  
- 只导出用户明确选中/整批确认样本；未审核纯模型框不得默认真值，除非用户勾选「将当前框视为已确认」。

#### M5.2 本机训练 — **可用现成权重跳过**

- Ultralytics YOLO **detect**；建议起步 `yolov8n.pt` / `yolov8s.pt`（适配 8GB）。  
- 独立 3.12 环境可重复命令；记录 epochs、imgsz、batch、device、划分。  
- 产出可加载权重 + 短摘要；失败须明确报错，不得静默落到演示框。  
- **当前默认**：`model_20261027_232748.pt`（6 类如上），首训可跳过。

#### M5.3 本机 YOLO 推理预标注 — **已实现（E2E GPU 待验）**

- `server/yolo_service.py`；`POST /api/annotations/yolo`；扩展 v1.4.0「预标注」。  
- 默认建议 `confidence=0.25`、`IoU=0.45`（服务端校验范围）；配置/请求可覆盖。  
- 输出 → 统一标注结构（原图像素 x/y/width/height + 项目类别）→ 已验证适配器写入。  
- 模型 `class_id` 必须对应导出 `classes.txt` / 项目类别表；未知类别拒绝写入。  
- 守卫：仅主动触发；已有标注不覆盖；切图/类别变更/非法/空结果不破坏数据；空结果为成功的「无框」提示。  
- 图片不发阿里云；千问预标注入口已退役。  
- 第一版以**当前单张**为主；整项目批量排队可另立项。  
- 状态：`GET /api/ai/status` → `provider: yolo`，`configured: true` 表示权重存在且可 import ultralytics。用法见 `docs/M5_3_YOLO_INFER.md`。

#### M5.4 迭代补标 — **不由本插件实现（2026-10-29）**

用户决定：审核修正后重新入集、再训等流程在**原网站**完成。本插件不交付 M5.4 工具链。

- 新权重仍可通过 **M5.5** 侧边栏接入/切换后用于预标注。  
- 不自动覆盖旧权重；切换须用户在侧边栏确认（M5.5 已实现）。

#### M5.5 侧边栏接入/切换本机 YOLO 权重 — **已实现（Edge×GPU 现场待验）**

用户需求（2026-10-29）：不希望只靠改 `.env` + 重启后端；要在**插件前端（侧边栏）**完成「人工训好的模型接入预标注」操作。

目标：在侧边栏提供本机 YOLO 权重的接入与切换入口，使换项目/换种子模型时无需手工改配置文件（或仅作兜底）。

第一版范围（最小可验收）：

1. 侧边栏展示当前生效权重（路径或文件名）及就绪状态（与 `GET /api/ai/status` 的 YOLO 字段一致或等价接口）。  
2. 支持从本机约定目录（默认 `server/models/`，可含子目录）**列出**可用 `.pt`，用户选择后设为当前预标注模型。  
3. 切换须**用户明确确认**；切换成功后后续「预标注」使用新权重；失败时保留原权重并提示原因（文件不存在、非 detect 权重、Ultralytics 加载失败等）。  
4. 切换结果持久化到本机服务侧（例如写入运行时配置或更新 `.env` 中的 `YOLO_MODEL_PATH`），扩展不保存模型二进制、不把权重上传云端。  
5. 类别名仍须与原网站项目类别**名称精确一致**；本功能不自动改网站类别表。  
6. **自动识别并展示模型内标签**：本机加载 `.pt` 后读取 Ultralytics `model.names`（有序类名列表），经本机接口返回；侧边栏在「当前权重」与切换成功后展示这些标签。可选：与当前原网站项目类别表做名称比对，标出匹配/未匹配项（仅提示，不自动改网站类别表、不自动改权重）。加载失败时不展示过期标签，并提示原因。

明确不做（第一版）：

- 浏览器内上传超大 `.pt` 到扩展再转发（可选后续；若做，须限大小、仅本机 `127.0.0.1`、不进 Git）。  
- 在侧边栏内发起训练或改超参。  
- 自动下载公网权重。  
- 多模型并行热切换无确认。  
- 根据模型标签自动创建/改写原网站项目类别。

与 M5.3 关系：M5.3 提供推理；M5.5 提供「选哪个权重」的 UX。原网站再训得到的新权重通过 M5.5 接入，而不是只改配置文件。

### M6 全量后现场候选 — **不由本插件实现（2026-10-29）**

用户决定：项目图全部确认后的全量导出与现场候选训练在**原网站**完成。本插件不交付 M6。

- 若现场候选权重也要用于本插件预标注，仍走 **M5.5** 接入，且须用户确认后才切换。  
- 板端转换/上线不在本规格插件范围。

## 8. 数据与接口约定

### 8.1 统一标注结构

内部：**原图像素**，左上原点，x 右 y 下；框为 `x, y, width, height`。不用页面缩放像素存数。

```json
{
  "schema_version": "1.0",
  "image_id": "本次加载图片的唯一标识",
  "image_width": 1000,
  "image_height": 800,
  "source": "mock",
  "objects": [
    {
      "id": "box-1",
      "class_id": 0,
      "class_name": "part_A",
      "x": 100,
      "y": 80,
      "width": 200,
      "height": 160
    }
  ],
  "review_status": "pending"
}
```

- 正式接入以原网站项目类别及稳定 ID 为准；演示 `part_A`/`part_B` 不硬编码进平台数据。  
- 坐标有限、宽高 > 0、框在图内；类别来自项目表，不按图临时重编号。  
- 非法返回报错，不写入。缩放按比例显示；留白偏移不计入原图坐标。  
- `review_status: pending` 为历史测试字段，**不**表示插件管理审核；适配时不据此推进网站审核态。  
- 适配器转为网站结构；若网站有来源字段可记模型来源，不擅自加平台不支持字段。  
- 最终保存/导出格式由原网站决定；插件不以 JSON/YOLO 下载作为预标注完成出口。

YOLO 标签换算（训练导出 / 测试工具参考）：

```text
x_center = (x + width / 2) / image_width
y_center = (y + height / 2) / image_height
width_normalized = width / image_width
height_normalized = height / image_height
```

### 8.2 本机 HTTP（`http://127.0.0.1:18000`）

端口说明：2026-10-02 因 8000 占用改为 **18000**；扩展与演示页同源校验已同步。

| 方法 | 路径 | 说明 | 状态 |
| --- | --- | --- | --- |
| GET | `/health` | 健康检查 | 现行 |
| GET | `/demo/` | 本地测试页 | 现行（测试辅助） |
| POST | `/api/annotations/mock` | 模拟框；不上传图、不调模型 | 现行 |
| POST | `/api/annotations/yolo` | 本机 YOLO 预标注 | **现行主路径** |
| GET | `/api/ai/status` | 就绪态；现行以 YOLO 为准 | 现行 |
| POST | `/api/examples/*`、`/api/references` | 示例库 | **已移除（0.7.4）** |
| POST | `/api/annotations/ai` | 历史千问预标注 | **已退役，勿再接** |

Mock：按原图比例 x=10%、y=10%、width=20%、height=20%。尺寸 1～1_000_000 整数；`image_id` 去空白后 1～256 字符；非法 → HTTP 422。

请求期禁重复操作；页面侧约 30s、后台网络约 25s 超时量级（与既有实现一致）。失败保留已有数据。

### 8.3 示例库存储

**已移除（0.7.4）。** 历史实现曾用 `server/references/`；目录若仍存在视为用户数据，代码不再读写。


### 8.4 写入守卫（约束适配器与扩展）

- 无图 / 原图未就绪 / 播放中 / 已有标注 → 不写。  
- 请求中切图、类别表变更、迟到响应 → 丢弃，不污染他图。  
- 重复点击不叠加重复框。  
- 坐标与类别校验失败 → 提示，不写。  
- 同类多实例：每个可辨认独立物体各一框，复用同一 `class_id`；不应用一个大框包多个独立板件（适配器/测试仍按此验收多框）。

### 8.5 扩展消息与架构要点

- Manifest V3；sidepanel ↔ background ↔ content ↔ MAIN。  
- 消息带版本/类型/`requestId`；校验来源与目标 tab；页面消息不可信作鉴权。  
- 后台只连固定本机地址，不接受页面指定任意 URL。  
- 真实预标注入口：侧边栏用户点击（及受约束的 Enter）；`isTrusted` 在真实用户入口校验。

## 10. 验收标准（现行）

### M5 必须通过

1. 能导出至少一套 YOLO detect 训练集（图 + labels + 类别表），约 50 张种子可复现；不进 Git。  
2. 本机 3.12 + Ultralytics 能完成一次训练并产出可加载权重，**或**文档标明使用的现成权重与类别表；失败有明确错误。  
3. 侧边栏对本机 YOLO 空标注图预标注，框写入后可用原网站工具编辑；坐标与类别映射正确。  
4. 已有标注、切图、非法输出、空结果不破坏数据；不跳过人工审核。  
5. 模拟路径仍可用；YOLO 预标注不把图片发往阿里云；千问预标注入口不可用。  
6. 自动化可用伪造/轻量权重覆盖导出格式、类别映射与写入守卫；**真实 GPU 训练与真实图效果须单独记录，不得与单测混称为同一验收。**  
7. **（M5.5）** 侧边栏可查看当前权重，并从本机约定目录选择 `.pt` 切换；确认后预标注走新权重；失败保留旧权重；权重文件不经云端、不进扩展打包。切换或查看当前权重时，侧边栏展示该权重内嵌标签（`model.names`）；与项目类别不一致时仅提示，不自动改网站类别表。

### M6（不由本插件验收）

1. 全量已确认标注可导出为 YOLO detect 集。  
2. 能按文档训出与辅助权重分目录保存的现场候选权重。  
3. 训练数据不含未审核默认框；用户确认前不自动切换预标注默认模型。

### 基线回归（已完成阶段，改动时勿破坏）

- **M1**：health；扩展在本地 demo 出模拟框；无图不请求；1000×800 → (100,80,200,160)；缩放对齐；停服可提示可重试；切图不污染；不重复叠框。  
- **M2**：读图/尺寸/标识/类别；模拟框进原生数据可编辑；不自动提交审核；已有标注与迟到响应守卫；空/失败提示。  
- **历史 M3 仍约束代码的部分**：统一结构校验；非法坐标/未知类别不写；密钥不进扩展；多实例同分框回归。千问调用本身不再验收。

### M4（可选并行）

相近难度图对比纯人工 vs 辅助总耗时；报告样本量与均值/中位。暂不承诺固定提升倍数。
